# p1 receipt単位の着地表示 — 実装・受入証跡

## 結論

repoのpush状態と、runが受理したreceiptのcanonical default branch着地を独立に表示できるようにした。
既存の `todo done` → `run intake accept` の順序は変えず、accept直後に
`.team/scripts/done.sh --landing-run <ref>` を呼ぶlanding-only modeを追加した。

## 実装

- source commit: `8eb7a6e`、引数契約補正 `6ff309b`
- `skill/templates/done.sh`
  - `--landing-run <ref>` で公開 `lattice run landing` を読み、`accepted_receipts[].landed` が
    falseの件数を `未着地 N本` として警告する。
  - 警告・CLI不調・upstream未設定は `todo done` や後続工程を止めない。
- `skill/templates/member.md`
  - managed runの正規順序を `todo done` → `accept` → landing-only表示として明記した。
- `skill/scripts/teardown.sh`
  - active runごとのlanding reportをschema検証し、同じreceipt件数を表示する。
- `.team/scripts/done.sh` はsetup時にtemplateから生成される管理外runtimeで、現在のrepoには存在しない。
  正本templateを更新したため、次回setupされる卓へ同じmodeが配布される。

## 受入実測

実Lattice保存run `.lattice/runs/t19-live-1`（accepted receipt 3本）を使う隔離temp repoで
`node experiments/teardown-landing-repro.mjs /Users/kite/Developer/Lattice` を実行した。

- upstreamのpush先はlocal HEADと一致させ、`repository.unpushed_commits=0` を実測した。
- default branchはreceipt 3本を含まないrefへ分け、done/teardown双方が `未着地 3本` を出した。
- upstream設定を外してもlanding-onlyはexit 0で壊れず、未着地警告を維持した。
- `--landing-run` のrun ref欠落は専用usage errorで非0になり、task_id経路へ落ちない。
- default branchを3 receiptすべての子孫へ替えると、push/receipt両方greenになり未着地警告は0件だった。
- `bash -n`（done/teardown）、`node --check`、`git diff --check` はgreen。
- `--failing-cli` と `--unusable-cli` はteardownが非0かつ `[未実施]` を出し、読めない状態を
  greenへ丸めなかった。
- `--without-landing` はlanding段を除いた欠陥版で期待どおり受入assertが失敗し、負側を確認した。

実行時に作るrepo・remote・room・run copyはすべてtemp配下で、終了時にserverを停止しtempを削除した。
