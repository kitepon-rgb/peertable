# t1: room/server.mjs — 稼働状態SSE・承認待ち表示・発言逐次出現・effort表示

## 何を作ったか（room/server.mjs 単独所有）

- (a) `POST /members`: 既存 record と merge 後の record を比較し、`status`/`busy_since`/`vendor`/`model`/`effort` のいずれかが変わった時だけ `event: member` を `room.streams` へ流す `emitMember()` を追加。`status_at`/`pane_token_hint` は判定対象から除外（頻繁に変わるため）。`post()` は呼ばない・log.jsonl へは書かない。新規参加(`!known`)時は流さない（既存 system 発言が refreshMembers を起こす）。
- (b) UI: `es.addEventListener('member', ...)` を追加。150ms デバウンスで既存 `refreshMembers()` を呼ぶ。`setInterval(refreshMembers,30000)` は退席検知の保険として維持。
- (c) 承認待ち(blocked)表示: CSS変数 `--blocked` を light/dark 両方に追加、`.chip .st.blocked` の点灯色、`.chip.is-blocked .av` に busy(`seat-working`揺れ)とは別種の緩い明滅(`seat-blocked` opacity pulse)を追加。ラベル辞書へ `blocked:'承認待ち'` 追加。継続時間表示の条件を `busy` から `busy||blocked` へ拡張。`reduced-motion` で無効化。
- (d) 発言の逐次出現: ライブ新着時だけ `.bubble` に `reveal` クラスを付け、直下の各ブロックへ `Math.min(i,8)*90ms` の `animation-delay` を設定。`block-in` keyframe(opacity+transform、`animation-fill-mode:both`)。過去ログ一括読込(catchUp)には付かない。`reduced-motion` で無効化。
- (e) effort表示: `vendor`/`model`/`effort` を1行 `claude / sonnet / high` 形式へ畳み、「effort」という語を削除(`launch-seat.sh:108` の着席ログ表記と揃える)。

## どう確認したか（実測）

`DATA=$(mktemp -d) PEERTABLE_PORT=18790 PEERTABLE_DATA="$DATA" node room/server.mjs`（着手前に port 18790 使用を room [7] で宣言）で自前起動し、`curl -N .../events` を張った状態で `curl -X POST .../members` を連投。

1. `alice` を `idle` で新規登録 → member イベントなし(新規のため。仕様通り) / system 発言1件のみ
2. `status: idle→busy` → `event: member` が1回出る(①確認)
3. `status_at` だけ変更 → member イベントなし(②確認)
4. `pane_token_hint` だけ変更 → member イベントなし(③確認)
5. `status: busy→blocked` → `event: member` が出る(④確認)
6. `log.jsonl` は最初の参加行1件のみで、上記2〜5では増えない(⑤確認、`wc -l`で確認)
7. `curl http://localhost:18790/testroom` の HTML に `.chip .st.blocked` / `.chip.is-blocked .av` / `seat-blocked` keyframe / `.bubble.reveal>*` / `block-in` keyframe / `memberDebounce` / `es.addEventListener('member', ...)` / `idParts` 畳み込みロジック / ラベル辞書 `承認待ち` が実在することを確認
8. `bob` を `{vendor:claude, model:sonnet, effort:high}` で登録し `GET /members` が3欄とも返すことを確認(UI側の idParts join で `claude / sonnet / high` になる入力)
9. `node -c room/server.mjs` で構文確認。プロセスは検証後に kill、一時 DATA dir は mktemp の自然揮発に任せる（本番 room には触っていない）

**ブラウザでの目視は未実施。** 上記はサーバー応答・HTML断片・SSEイベント内容の実測のみで、実ブラウザでのアニメーション見え方(揺れ/明滅/逐次出現の視覚確認)は行っていない。
