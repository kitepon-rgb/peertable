# t2: skill/scripts: effort を必須引数化し、承認待ち(blocked)を判定する

## 変更ファイル

- `skill/scripts/launch-seat.sh`
- `skill/scripts/seat-usage.mjs`
- `skill/scripts/seat-status-bridge.mjs`
- `experiments/seat-status-blocked-repro.mjs`（新規）

## (a) effort を必須引数化

- usage を `<project_dir> <name> <model> <vendor> <effort> [brief]` へ変更。`vendor`・`effort` とも未指定なら
  usage を出して非ゼロ終了する（従来は `vendor` に既定値 `claude`、`effort` は任意）。
- claude の level は `low|medium|high|xhigh|max` の集合で、着席を試みる**前**に弾く
  （`change-effort.sh:46-48` と同じ集合）。
- codex 側は catalog 照会を複製しない（CLI が落ちるのに任せる）。
- `launch-seat.sh` を呼ぶ既存の呼び出し元（`change-effort.sh`）は元から6引数フル指定なので無改修で通る。

## (b) 承認待ち(blocked)の判定

- `seat-usage.mjs` へ純粋関数 `classifyPaneTail(tail)` と `BLOCKED_MARKERS` を追加
  （`parsePaneTokenHint` と同じ「vendor I/O を持たない・repro から直接叩ける」形に合わせた）。
- 判定順は busy → blocked → idle。marker は launch-seat.sh:74-77 と docs/plan.md §11 が実測記録した4種
  （`1. Yes, I trust this folder` / `1. I am using this for local development` / `1. Yes, continue` /
  `Do you want to proceed?`）。
- `seat-status-bridge.mjs` の `readSeat` を `classifyPaneTail` 経由へ差し替え、`busySince` は busy・blocked
  どちらでも継続時間を持つ（フィールド名は `busy_since` のまま——UI 側(t1)が承認待ちの継続時間を出す前提）。

## (c) 判定の再現ハーネス

`experiments/seat-status-blocked-repro.mjs` を新規に置いた。

- ① 既知ダイアログ文言4種それぞれで `blocked` が返る
- ② `esc to interrupt` が同時に在れば `busy` が勝つ
- ③ どちらも無ければ `idle`

## 検証

```
$ node experiments/seat-status-blocked-repro.mjs
seat status blocked repro: 7/7 green
$ node experiments/seat-usage-repro.mjs   # 既存 repro が壊れていないことの確認
seat usage repro: 9/9 green
$ bash -n skill/scripts/launch-seat.sh
（構文エラーなし）
```

実測: `launch-seat.sh` を effort 無しで叩くと usage を出して非ゼロ終了。`effort=bogus` で叩くと
「unknown effort: bogus（claude は low|medium|high|xhigh|max）」で非ゼロ終了（いずれも着席を試みる前）。
usage 呼び出しも非ゼロ終了する。**席を実際に立てる検証はしない**（卓の席と衝突するため。設計メモの指定どおり）。
