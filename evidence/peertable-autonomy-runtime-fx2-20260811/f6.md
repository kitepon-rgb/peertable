# f6 receipt 未 accept でも ToDo done が先行し、着地しないまま完了に見える

担当: suzune（claude / opus / high）。

## 1. 欠陥（一次情報・自分で踏んだ）

2026-08-11、t1 の完了処理で次が起きた（room [42][45]）。

1. `lattice run intake accept --run <run> --task t1` が `RUNTIME_CONFLICT_HOLD`
   （`undeclared_write`: `experiments/seat-change-repro.mjs`, `room/client.mjs`）で**失敗**した。
2. それでも `.team/scripts/done.sh t1 --evidence-from …` は**成功**し、ToDo は done になった
   （journal seq3）。出力は `未push 4本` だけで、receipt が受理されていない事実には触れない。
3. `.team/scripts/done.sh --landing-run <run>` も**無言**だった——landing report は
   accepted receipt しか持たず、受理前で止まった intake は 0 本として数えられるため。
4. 結果として「ToDo は完了・成果はどこにも着地していない」状態が、親の事後照合
   （`run landing` = `landed:false` / `accepted_receipts:[]`）まで誰にも見えず、t1 は reopen された。

実行層に載せた task の成果の正本は Lattice が撮った observed diff（accepted receipt）であって、
ToDo の done ではない。done.sh はその順序を機械的に守らせていなかった。

## 2. 直したもの

`skill/templates/done.sh`（配布正本。卓の `.team/scripts/done.sh` は setup が配る同内容）。

**receipt gate**（`todo done` の直前）:

- `run list --json` から、当該 plan の active な **pull** run を集める。
- 各 run を `run observe` し、当該 task の intake を探す。
  - `accepted_head_sha` が空（＝未 accept）→ **done を打たずに落ちる**。
    次に打つべき command（`lattice run intake accept --run <ref> --task <id>`）を名指しし、
    「accept が hold で止まるならその解消が完了条件であって done は迂回路ではない」と明示する。
  - intake が無い（実行層に載っていない）→ **素通し**。pull run の利用は任意で、載っていない卓は止めない。
- `run list` / `run observe` を読めない時は、**通さずに落ちる**。状態不明を成功へ倒さない
  （黙って別経路へ落ちない・無根拠な safe default を置かない）。

**landing-only mode の軸を分けた**: 「受理済みだが未着地」に加えて、
「そもそも受理されていない intake が在る」を別行で出す（`未accept: run <ref> …`）。
今回はこの軸が無かったので、受理前で止まっていることを landing 側からは読めなかった。
