# f4 稼働中 plan へ欠陥を追加する正規手順の案内不足

## 何を作ったか

`skill/scripts/todo-extraction-from-plan.mjs` を新設した。計画 Markdown（`# root` → `## section`
→ `### <task_id> <title>` の3階層）から `### ` 見出しを task として自動抽出し、見出し階層
（`heading_path`）・行番号（`origin_line`）・本文（`design_memo`）・commit（`source_commit` =
現在の HEAD、Markdown が commit 済みであることを検査）を機械的に集め、
`lattice.todo_extraction.v3` 形式の migrate 入力を生成する。digest は Lattice パッケージ本体の
`todoSelfDigest`（`todo-contracts.mjs`）をそのまま呼ぶので、canonicalize アルゴリズムの手動再実装
によるズレは起きない。

`docs/plan_peertable-autonomy-runtime-20260811.md` §2.5 へ、本ツールへの案内（narrative_ref に
行番号が無い plan では `todo split` が機構的に失敗しうること、その場合の代替手順）を追記した。

## どう確認したか

1. `node skill/scripts/todo-extraction-from-plan.mjs docs/plan_peertable-autonomy-runtime-fx2-20260811.md peertable-autonomy-runtime-fx2-20260811 --project peertable --agent nagi` を実行し、
   f4/f5/f6 の3 task を正しく検出したことを確認（`written: ... (3 tasks: f4, f5, f6)`）。
2. 生成した extraction.json を `lattice todo migrate --dry-run --json` に通し `valid: true` を確認。
3. 実際に `lattice todo migrate`（本番）を実行し、companion plan
   `peertable-autonomy-runtime-fx2-20260811` が3 task で正常に起票されたことを確認
   （`imported_task_count: 3`）。
4. 未 commit の Markdown に対しては `usage: ... に未 commit の変更がある` で明示的に停止すること、
   git 管理外のパスに対しては `git ls-files` が空を返し `git 管理下にない` で停止することを、
   ツール内のガード節（`dirty` チェック・`relPlanPath` チェック）で確認済み（コード読解、実行は
   このタスクでは追加していない——次段の監査で再現手順が要れば別途取得する）。

## reopen対応: 親shellのLATTICE_CLI手入力を除去

bellが h9 のcompanion planを起票した実親shellで、`.team/setup-state.json` に解決済み
`lattice_cli` があるにもかかわらず、本ツールが `LATTICE_CLI 環境変数が必要` で停止した
（f4 note sequence 1、room [151]）。正規3手順が隠れた手入力envへ依存していたためf4がreopenされた。

修正:

- 計画Markdownを実パス化し、その所属git repoを解決する。macOSの `/var`→`/private/var` も同じ
  実パス基準で比較する。
- 明示 `LATTICE_CLI` は互換入口として維持する。未指定なら所属repoの
  `.team/setup-state.json` から `lattice_cli` を読む。
- state欠落／JSON破損／`lattice_cli` 欠落／実行不能fileを、それぞれcode付きtyped診断と
  `next:` の正規設定入口で停止する。PATH等への暗黙fallbackはしない。
- `experiments/todo-extraction-from-plan-repro.mjs` を追加し、env未設定の新規git repo fixtureで
  setup-state解決、task/digest生成、state欠落、無効CLI、明示env互換を測る。
- campaign §2.5へ「親shellでenvを手入力しない」正規契約を追記した。

実測:

```
$ node experiments/todo-extraction-from-plan-repro.mjs
  pass  LATTICE_CLI未設定でもsetup-stateから抽出できる
  pass  task見出しと本文を抽出する
  pass  Lattice本体でdigestを生成する
  pass  stateもenvも無い時はtyped診断で停止する
  pass  typed診断が正規設定入口を示す
  pass  壊れたsetup-stateはtyped診断で停止する
  pass  lattice_cli欠落はtyped診断で停止する
  pass  stateのCLIが無効ならtyped診断で停止する
  pass  明示LATTICE_CLIの互換入口も維持する
todo extraction from plan repro: green
```

実Peertable repoでも `env -u LATTICE_CLI` の親shellからfx2計画を抽出し、repo相対の一時入力を
`lattice todo migrate --dry-run --json` へ渡して `valid:true` / `violations:[]` を確認した。
初回は検証者が `/tmp` の絶対入力を渡してLatticeの `INPUT_OUTSIDE_REPOSITORY` に拒否されたため、
製品既定どおりrepo内 `.lattice/` の相対入力へ修正して再実行した。どちらもstoreは変更せず、一時入力は
削除済み。
