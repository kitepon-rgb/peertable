# t4: launcher と他ブリッジを記述子へ追従

## 実装

- launcher と teardown の socket 解決を `tmux-socket.mjs` へ統一した。
- launcher の member metadata に `observe` を記録し、読み返しでも確認するようにした。
- wakeup bridge と teardown は member ごとの記述子を優先して tmux target/socket を選ぶ。
- wakeup bridge の SSE 接続成功と run bridge の最初の `run list` 成功で `ready_at` を原子的に記録する。
- archive の `--members --json` を追加し、空白を含む member 名でも teardown の停止・解除が壊れないようにした。

## 確認

- 使い捨て HTTP server に対して `archive-room-log.py --members --json` を実行し、記述子を含む member 配列を読み戻せることを確認した。
- `bash -n skill/scripts/launch-seat.sh`、`bash -n skill/scripts/teardown.sh`、
  `node --check skill/scripts/wakeup-bridge.mjs`、`node --check skill/scripts/run-bridge.mjs`、
  `python3 -m py_compile skill/scripts/archive-room-log.py`、`git diff --check` が成功した。

## reject 修正（2026-08-11）

- Codex closed env の `TMUX` / `TMUX_PANE` は、launcher の pane ではなく新しく作った
  session の `#{socket_path}` / `#{pane_id}` から渡すように修正した。
- wakeup bridge は配達ごとに member 一覧を更新し、登録後の席も記述子または legacy target へ配達する。
- teardown の空 member 行は処理しない。
- 使い捨て tmux server で `#{socket_path}` と新 session の `#{pane_id}` を実測し、shell/Node 構文検査と
  `git diff --check` を再実行した。
