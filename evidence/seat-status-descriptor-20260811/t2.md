# t2 証跡 — bridge と client を記述子ベースにする

## 実装

- `seat-status-bridge.mjs` は room member オブジェクトを保持し、`observe` 記述子の socket / target を優先して観測するようにした。
- 既定 socket は legacy member が必要とした時だけ解決する。記述子だけの卓は曖昧な既定 socket に依存しない。
- 初回の members 取得・capability 判定成功後、`ready_at` を temporary file から rename する原子的な更新で記録する。
- `client.mjs` は `$TMUX` と `$TMUX_PANE` から自己の socket / session 名を取得して参加登録に載せる。取得できない時は `observe` を省略し、stderr に理由を出す。

## 検証

- `node --check skill/scripts/seat-status-bridge.mjs`
- `node --check room/client.mjs`
- `node experiments/seat-socket-discovery-repro.mjs` → 7/7 green
- `node experiments/seat-observe-descriptor-repro.mjs` → 4/4 green
- `node experiments/seat-status-socket-repro.mjs` → 4/4 green
- 使い捨て room（port 18861）と使い捨て tmux socket で実測: client の `observe` 登録、bridge の非 `peer-` target 観測、`ready_at` 記録、既定 socket 未使用の診断出力を確認。
- tmux 外の client を同じく使い捨て room で実測: `observe` が登録されず、`peertable-client: observe unavailable: TMUX 不在` が stderr に1行出ることを確認。
