# r3 — Codex管理席へroom MCPをproject設定から装備

実施日: 2026-08-12

## 原因と実装

- 親のlive再着席で、Aiterm launch receipt成功後もCodex席がroom member登録せず、
  `SEAT_ROOM_MCP_NOT_READY`でrollbackした。
- `.mcp.json`のroomは`codex mcp list`に現れず、同じcwdの`.codex/config.toml`へ置いたroomは
  現れることを親が実測し、Claude用設定をCodexも読むという前提誤りを原因として確定した。
- `ensure-codex-room-mcp.mjs`を追加し、Codexのproject設定へPeertable所有marker付きのroom MCP blockを
  追加・更新・撤去する。既存の他設定は保持し、project所有の同名room blockは上書きしない。
- setupで自動装備し、旧setup済みroomはlaunch直前に追補する。teardownはmarkerで所有したblockと
  git excludeだけを撤去する。Aiterm本体、Codex launcher、wrapperは変更していない。

r3 harnessは、既存configのbyte復元、対象projectのgit exclude所有、seat環境の明示継承、setup／launch／teardown
配線に加え、実Codex CLIの`mcp list`がprojectの`room`を認識することを確認し、診断用configをfinallyで撤去した。

## 最終自己監査

- Aiterm本体、実席、`change-seat.sh`、旧t4所有物には書込みをしていない。
- 対象差分の`git diff --check`は成功した。live再着席とmodel／effort変更はi1で親が改めて行う。
