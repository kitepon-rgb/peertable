# c2 稼働席設定変更の公開Aiterm経路

実施日: 2026-08-12

## 実装

- room clientは `AITERM_SESSION_ID` を `aiterm_session_id` としてmember metadataへ登録する。
- 同一vendorの変更は、保存されたmanaged session idに対して公開
  `agent_configure` をstdio MCP adapterで呼ぶ。adapterは親の実行時環境を継承し、
  Aitermのsession metadataと同じruntime state rootを参照する。
- 成功receiptの後だけroom member metadataを更新し、読み返しと履歴記録を行う。
- vendor変更は既存再起動経路を維持する。managed session idが無い同一vendor席は
  `SEAT_CHANGE_AITERM_SESSION_MISSING` で変更せず停止する。

## 実測

破棄可能なmanaged Codex session `c2-configure-fixture3` で、Peertable adapterを通して
同一session idへ次を順に実行した。

- model-only: `gpt-5.6-terra`（receipt effortはnull）
- effort-only: `low`（receipt modelはnull）
- 同時変更: `gpt-5.6-luna / medium`

いずれも `aiterm.agent-configure-result.v1` を返し、TUIには
`terra medium`、`terra low`、`luna medium` が同一contextのまま連続表示された。fixtureは閉鎖済み。
