# t1: 単独円卓モード（決定47）の実装

担当: つむぎ / plan: roundtable-improvement / 正本計画: `.team/campaign-plan.md` 項目1

## 何を作ったか

Lattice 無しで円卓を立てられる工程正本の分岐を入れた。ミニタスクトラッカーは作っていない（決定36）。

- **`skill/scripts/setup.sh`**: 引数を `<project_dir> <room> <server_url> <plan_key|-> <peertable_repo> [tasks_file]` に拡張。`plan_key` が `-`（または空）なら単独円卓モード。
  - 単独時: `templates/member-standalone.md` を `.team/roles/member.md` として配り、`templates/tasks.md`（説明ヘッダ）と第6引数の本文を連結して `.team/tasks.md` を生成する。`.team/scripts/done.sh` は配らない（Lattice 前提のため）
  - 単独時に議題表が渡されなければ **project へ何か置く前に** エラー終了する（空の議題表を黙って作らない／半端な `.team/` を残さない）
  - `.team/setup-state.json` に `"mode":"lattice"|"standalone"` を追加。既存キーは全て維持したので `teardown.sh` は無変更で動く
- **`skill/templates/member-standalone.md`（新規）**: 単独モードの作業ループ（tasks.md で議題を見る → room で claim → 実装 → pathspec 明示 commit → room へ完了報告）。Lattice・done.sh・evidence への言及なし。進行の正本は room の宣言だけであることを明示
- **`skill/templates/tasks.md`（新規）**: 議題表のヘッダ。読み取り専用であること・状態を持たないこと・依存の機械保証が無いことを書いてある
- **`skill/templates/charter.md`**: 条項1 を「拘束力を持つのは**工程正本への記録**と room での決定だけ」へ抽象化（工程正本＝併用なら Lattice の todo 記録、単独なら room の宣言そのもの）。条項3（タスクの呼び名）・条項6（次の着手可能の確認先）を両モード対応へ
- **`skill/SKILL.md`**: 前提の `lattice` CLI を「Lattice 併用モードのみ」へ／聞き取りへ工程正本の分岐と選び分けの基準を追加／手順3 の scaffold 引数を更新／手順4 を「併用モードのみ」とし単独のタスク正本を明記／手順5 の env を分岐（単独は `PEERTABLE_PLAN`・`LATTICE_TODO_ACTOR_*` を渡さない）／手順7 の起動確認を分岐／親の operating notes へ単独モードの督促検出源と done gate（全議題の完了報告を room ログで確認して散会宣言）を追加
- **`skill/SKILL.md` の既存バグ1件を訂正**: teardown の呼び出しが `teardown.sh <project> <room> <server_url>` と書かれていたが、実物の `scripts/teardown.sh` は引数1個（`<project_dir>`。room 名と URL は `setup-state.json` から読む）。room [12] で開示し [13] であかりの同意を得て t1 内で直した

`skill/scripts/teardown.sh` は無変更（計画どおり）。

## どう確認したか

scratchpad に使い捨ての git repo とローカル room サーバー（`peertable-room` を 127.0.0.1:18899・データも scratchpad）を立てて実測した。**本番 room サーバー（192.168.1.2:18860）には触っていない**（teardown が room を DELETE するため）。

1. **単独モードの scaffold**: `setup.sh <tmp> testroom http://127.0.0.1:18899 - <repo> <tasks-src.md>`
   - 生成物: `.team/CLAUDE.md`・`.team/roles/member.md`（1行目が「# メンバー役割（単独円卓モード）」＝単独版）・`.team/tasks.md`（ヘッダ＋渡した議題2件）・`.team/setup-state.json`（`"mode":"standalone","plan_key":""`）・root `.mcp.json`。**`.team/scripts/done.sh` は生成されない**
   - `.git/info/exclude` へ `.team/` と `/.mcp.json` が入り、`git status --porcelain` は空
2. **議題表なしで単独モードを呼ぶ**: `ERROR: 単独円卓モードは議題表の本文ファイル（第6引数）が必須` を stderr へ出して `exit=1`。project ディレクトリには**何も残らない**（`.team` すら作られない）
3. **単独モードの teardown**: `teardown.sh <tmp>` が `exit=0`。`.team/` と `.mcp.json` が消え、`.git/info/exclude` は元の内容へ復元、`git status --porcelain` は空（**diff ゼロ**）。サーバー側も room が消えた（members が空・データディレクトリも削除）
4. **従来引数の後方互換**: HEAD 版の skill 一式（`git archive HEAD skill`）と新版を、同じ従来5引数で別々の tmp repo へ流して `diff -ru`
   - 生成ファイルの構成: **同一**（`CLAUDE.md` / `roles/member.md` / `scripts/done.sh` / `setup-state.json`）
   - `roles/member.md`・`scripts/done.sh`・root `.mcp.json`: **バイト同一**
   - 差分は意図した2点だけ: `CLAUDE.md`（憲章の条項1・3・6 の両モード対応）と `setup-state.json` の `"mode":"lattice"` キー1個の増加
5. **teardown の非回帰**: 新版で作った Lattice 併用 scaffold、および **`mode` キーを持たない旧 state** の scaffold、どちらも `teardown.sh` が `exit=0` で diff ゼロまで戻した（teardown は `mode` を読まないので旧 state と互換）

## 実測で分かった申し送り

`lattice todo start --plan roundtable-improvement --task t3 --parallel-frontier` は、independence が未 compile な plan では `PARALLEL_DISPATCH_INVALID / parallel_frontier_not_applicable` で弾かれ、フラグ無しの `start` が通った（本 campaign で実際に発生）。`templates/member.md` の作業ループ手順3 と `SKILL.md` 運用知識は `--parallel-frontier` を無条件で指示しているため、実運用で最初の1コマンドが必ずコケる。t1 の受入条件外なので手を入れていない。room で開示済み。
