# h2 証跡 — launch-seat の brief 輸送と着任 turn 観測

## 実施

- `skill/scripts/launch-seat.sh` の brief 処理を修正した。
  - brief を着席処理より前に byte 単位で検証する（上限 65536 bytes）。
  - 受理した brief は一時 file と named tmux buffer 経由で貼り付ける。
  - submit 後、tmux の scrollback に `esc to interrupt` が投入前と異なる状態で現れるまで観測する。
  - 上限超過・輸送失敗・turn 未開始を typed error token で返す。
  - `EXIT` cleanup が元の終了コードを上書きしないようにした。
- `experiments/launch-brief-repro.mjs` を追加した。実 tmux と fake CLI で、欠陥版の負例、修正版の長文輸送、上限超過の副作用なし拒否を分離して測る。

## 受入実測

1. 欠陥版は同じ 12006 bytes の brief を `send-keys` へ渡すと `command too long` で失敗し、着席用 tmux session が先に作られる。
2. 修正版は同じ brief を `load-buffer` / `paste-buffer` で送り、`send-keys Enter` 後の turn marker を観測して `briefed` を返す。
3. 65537 bytes の brief は `LAUNCH_BRIEF_TOO_LONG`・終了コード2で、model preflight、tmux、seat identity を一つも発生させずに拒否する。
