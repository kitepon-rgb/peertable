# h2 証跡 — launch-seat の brief 輸送と着任 turn 観測

## 実施

- `skill/scripts/launch-seat.sh` の brief 処理を修正した。
  - brief を着席処理より前に byte 単位で検証する（上限 65536 bytes）。
  - 受理した brief は一時 file と named tmux buffer 経由で貼り付ける。
  - Codex のヘッダ表示後も MCP 初期化が続くため、入力候補行とモデルフッタを含む ready 状態を3回安定観測してから貼り付ける。
  - paste後に一拍置いてsubmitし、入力欄に本文が残ったままなら Enter を一度だけ再送する。
  - submit 後、tmux の scrollback に `esc to interrupt` が投入前と異なる状態で現れるまで観測する。
  - 上限超過・輸送失敗・turn 未開始を typed error token で返す。
  - turn 未開始時は tmux sessionを先に停止し、room memberのDELETEと一覧読み返し、seat identity撤去まで行う。rollback失敗は別のtyped errorで返す。
  - `EXIT` cleanup が元の終了コードを上書きしないようにした。
- `experiments/launch-brief-repro.mjs` を更新した。実 tmux と fake Codexで、ready前paste拒否、長文輸送、turn未開始のrollback、上限超過の副作用なし拒否を分離して測る。

## 受入実測

1. 欠陥版は同じ 12006 bytes の brief を `send-keys` へ渡すと `command too long` で失敗する。
2. 修正版はready前の `paste-buffer` を拒否するfake Codexに対してもreadyを待ち、同じ briefを `load-buffer` / `paste-buffer` で送り、turn markerを観測して `briefed` を返す。
3. turn未開始の負例は `LAUNCH_BRIEF_TURN_NOT_STARTED` を返し、tmux session・room member・seat identityを残さず `LAUNCH_BRIEF_ROLLED_BACK` を返す。
4. 65537 bytes の brief は `LAUNCH_BRIEF_TOO_LONG`・終了コード2で、model preflight、tmux、seat identity を一つも発生させずに拒否する。
5. 実 Codex CLI `0.147.0` の room `peertable-autonomy-runtime-20260811` で、`yuzu` / `rikka` / `kohaku` / `sumire` の4席を順次起動した。全席で `rc=0`、`seated`、`briefed`、metadata保存、`seat-status-bridge` 起動確認を得た。`peer-yuzu` ではCodexヘッダ、MCP startup warning後のbrief表示、SessionStart/UserPromptSubmit、`Working … esc to interrupt` をpaneで読み返した。roomのmember登録はseq183〜186、独立監査はseq187。
