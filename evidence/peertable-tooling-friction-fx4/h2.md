# h2 証跡 — launch-seat の brief 輸送と着任 turn 観測

## 実施

- `skill/scripts/launch-seat.sh` の brief 処理を修正した。
  - brief を着席処理より前に byte 単位で検証する（上限 65536 bytes）。
  - 受理した brief は一時 file と named tmux buffer 経由で貼り付ける。
  - Codex のヘッダ表示後も MCP 初期化が続くため、可視 pane の直近24行から入力候補行とモデルフッタを探し、ready を3回連続観測してから貼り付ける。MCP警告・hook表示の更新や画面全体の変化は判定に使わない。
  - ready後に一拍置き、briefを一度だけ pasteし、Enterを一度だけ送る。再送でexactly-onceを壊さない。
  - submit 後、tmux の scrollback に `esc to interrupt` が投入前と異なる状態で現れるまで観測する。
  - ready を確認できないだけの `LAUNCH_BRIEF_NOT_READY` は brief 未投入の空席を保持し、seat identity・metadata・bridgeまで後段セットアップしてAiterm 手動 dispatchへ引き継ぐ。brief投入後の turn 未開始・輸送失敗だけを真の失敗として扱う。
  - 真の失敗時は tmux session を先に停止し、room member の DELETE と一覧読み返し、seat identity 撤去まで行う。rollback失敗は別のtyped errorで返す。
  - `EXIT` cleanup が元の終了コードを上書きしないようにした。
- `experiments/launch-brief-repro.mjs` を更新した。実 tmux と Codex 0.147.0相当のfakeで、MCP/hook表示更新中のready、brief dispatch回数、NOT_READY空席保持、turn未開始のrollback、上限超過の副作用なし拒否を分離して測る。

## 受入実測

1. 欠陥版は同じ 12006 bytes の brief を `send-keys` へ渡すと `command too long` で失敗する。修正版は同じ brief を `load-buffer` / `paste-buffer` で送り、MCP/hook表示を動かしたまま `briefed` を返した。dispatch回数は1回。
2. ready 判定を成立させない負例は `LAUNCH_BRIEF_NOT_READY` を返し、`LAUNCH_BRIEF_ROLLED_BACK` を出さず、tmux session・room member・seat identity・metadataを空席として保持した。brief送信回数は0回で、Aiterm手動dispatchへ渡せる後段状態になった。
3. brief投入後にturnが始まらない負例は `LAUNCH_BRIEF_TURN_NOT_STARTED` を返し、tmux session・room member・seat identityを残さず `LAUNCH_BRIEF_ROLLED_BACK` を返す。
4. 65537 bytes の brief は `LAUNCH_BRIEF_TOO_LONG`・終了コード2で、model preflight、tmux、seat identityを一つも発生させずに拒否する。
5. 実 Codex CLI `0.147.0` の room `peertable-autonomy-runtime-20260811` で、`aoba` → `hotaru` → `sena` を連続3回起動した。全席で `rc=0`、`seated`、`briefed`、metadata保存、`seat-status-bridge` 起動確認を得た。各画面にX-HERMES-MCP / sprite-forgeのstartup warning、SessionStart/UserPromptSubmit hook更新、`Working … esc to interrupt`を観測した。検証後に4席のtmux・member・seat identityを対象限定で撤去し、共有bridgeは停止していない。room記録はseq204。
6. briefなしの `manualh2` を立て、Aiterm `pty_read` でMCP警告・hook後の入力promptと `gpt-5.6-luna max · ~/Developer/peertable` footerを観測した。Aiterm `pty_send` で本文を1回入力し、hook完了後に `pty_key(Enter)` を1回送ると `Working … esc to interrupt` へ遷移した。launch-seatの3席と同じ ready画面・dispatch後状態であり、検証後に対象限定で撤去した。
