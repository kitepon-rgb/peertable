# t12 room Web UIのスクロールボタン

担当 ichika。触ったのは `room/server.mjs` の内蔵クライアント（UI テンプレートの markup・CSS・JS）だけ。
API・SSE 配信・Markdown 描画には触っていない。`docs/plan.md` にも触っていない。

## 作ったもの

長いログを遡った後に最新へ戻る、円形の「↓」ボタン。ページ下部中央にフロートし、
**最下部に居る時は消える／遡ると出る／押すと最新へ戻る**。

- markup: `<button class="to-bottom" id="to-bottom" type="button" hidden aria-label="最新の発言へ">↓`
  （`<main class="log">` の後ろ。**`innerHTML` は使わない**——t10 と同じく既存の `el()`/`textContent` 様式を保つ）
- CSS: `position:fixed` の円形ボタン。`.to-bottom[hidden]{display:none}` を明示（`display:grid` が
  `hidden` を打ち消さないように）
- JS: **表示条件は既存の `nearBottom()` をそのまま使う**。SSE の自動追従と**同じ判定**にした——
  別々の閾値を持つと「ボタンは消えているのに追従しない」帯ができて、どちらが壊れたのか分からなくなる
- 更新契機は3つ: `scroll` / `resize` / **発言が増えた時**。3つ目が要るのは、発言が増えると body が伸びて
  **scroll イベント無しに「最下部か」が変わる**ため（`catchUp` と `onmessage` の両方から `syncToBottom()`）

## 検証

**測定器を先に用意した**（決定60）。負のコントロールは t10 時点の実装（`4605744` の `room/server.mjs`）を
取り出して別ポートで起動し、**同じハーネスで「ボタンが存在しない」ことを確かめてから**現行を読んだ。

環境: 使い捨て server 2本（**8812=現行 / 8813=旧版**・使い捨て DATA・**本番 room に不接触**）、
発言40件を投入して遡れる状態を作り、headless Chrome for Testing + CDP 9222（拡張なし・temp プロファイル）
で観測。すべて機械値（`document.getElementById('to-bottom')` と `window.scrollY` を読む）。

### 受入(1)(2)(3)

| 状態 | 旧版 8813（負のコントロール） | 現行 8812 |
| --- | --- | --- |
| 初期表示（最下部・scrollY 1226） | **ボタンが存在しない** | 存在し **hidden=true**（受入2） |
| 先頭へ遡る（scrollY 0） | 存在しない | **hidden=false**（受入1） |
| ボタンを押す | 押せない（`ボタンが無い`） | クリック成立 |
| 押した後 | scrollY 0 のまま | **scrollY 1226・最下部・hidden=true**（受入3） |

### 受入(4) SSE 新着の自動追従を壊さない

ページを開いたまま API へ実際に post して観測した。

| 場面 | 観測 |
| --- | --- |
| **最下部に居る時に新着** | scrollY 1226→1269・bodyHeight 1926→1969・**追従した**・件数 40→41・ボタンは hidden のまま |
| **遡っている時に新着** | scrollY **0 のまま**（追従しない＝既存挙動）・bodyHeight 1969→2012・件数 41→42・**ボタンは出たまま** |

既存の「最下部に居る時だけ追従する」挙動は保たれている。**追従とボタンが同じ `nearBottom()` を見ている**ので、
両者の状態が食い違う帯は構造的に存在しない。

目視: スクショ1枚（760x700・dark・遡った状態）。円形ボタンが下部中央に出ている。

## 残すもの

- ボタンは**ログの上に重なる**（フロートなので設計どおり）。下端の発言に一瞬かぶるが、
  最下部に居る時は消えるので、読んでいる最中に邪魔をする位置には出ない
- **light テーマでの目視は撮っていない**。CSS は `--surface`/`--line`/`--fg`/`--accent` のトークンだけを
  使っているので light 側でも成立するはずだが、**確かめていないので「はず」のまま残す**
- t14（haruka）の server 側がこの後同じファイルへ入る。私の変更は UI テンプレートの
  markup/CSS/JS だけで、`GET /members` にも `POST /members` にも触っていない
