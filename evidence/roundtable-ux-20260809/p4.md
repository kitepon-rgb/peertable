# p4 席ごとの消費目安表示 — 実装・検証証跡

## 結論

各席の詳細表示へ、paneが明示したtoken数とbusy継続時間を消費目安として表示した。
外部課金APIやvendor別単価は推測せず、paneにtoken表記が無い席はtoken値を表示しない。

## 実施

- source commit: `cc54ece`
- 監査補正 commit: `4097b2f`
- `skill/scripts/seat-usage.mjs`
  - pane末尾の`↓/↑ N[k/M] tokens`を整数token数へ正規化する。
  - serverの明示`member_observation_v1` capabilityだけを対応判定に使う。
- `skill/scripts/seat-status-bridge.mjs`
  - `busy_since`、`pane_token_hint`、観測sourceをmember任意欄へ送る。
  - token変化は1k粒度、状態は即時、無変化時は既存heartbeatで送る。
- `room/server.mjs`
  - GET membersへ明示capabilityを返す。
  - 席のtitleとタップ用popoverへ`消費目安 継続 … / … tokens（pane観測）`を表示する。
  - 開始1分未満は上方丸めせず`<1m`と表示する。

  - token表記4種、非表記3種、明示capability正側、status欄だけの旧応答負側。
- `node experiments/member-repost-noise-repro.mjs`: 4/4 green

  - capability `true`
  - `status=busy`
  - `busy_since`は文字列
  - `pane_token_hint=3400`
  - `usage_source=pane_status`
- 専用headless Chrome＋CDPで実UIを確認:
  - title: `消費目安 継続 <1m / 27.8k tokens（pane観測）`
  - タップ用popoverも同一内容
  - status classは`st busy`
- 検証用server・Chrome・tmuxを停止し、port 18812/18813/18814はLISTEN 0、
  process生存0、一時data/profile/project dir削除済み。

## 独立監査で見つかった欠陥と補正

- fresh memberにstatus欄が無いだけで未対応serverと誤判定していたため、保存データではなく明示capabilityへ変更した。
- busy開始直後を`1m`と上方表示していたため、1分未満を`<1m`へ変更した。
