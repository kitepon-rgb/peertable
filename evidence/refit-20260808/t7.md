# t7 setup.sh外部ペイン登録のproject_id不一致修正

担当 ichika。触ったのは `skill/scripts/external-pane.mjs` と新規の `experiments/external-pane-project-id-repro.mjs` だけ。
`setup.sh` は変更していない（呼び出し方は変わらないため。bell [182] の直列化 t7→t8 は空いたまま）。

## 直した欠陥

`external-pane.mjs` は project_id を **ディレクトリ名**から決めていた。Lattice store を既に持つ
project では store の `project_id` が別の値（例: PascalCase ディレクトリ × kebab-case store）でありうる。
identity 文書の `project_id` が store と食い違うと `resolveProjectIdentity` が
`PROJECT_IDENTITY_INVALID / identity_schema_invalid` を投げ、**`lattice todo status` ごと死ぬ**
——工程正本が読めなくなるので claim も done も取れなくなる。

**前campaign で「コネクタの出力を検証器に通して一致」と報告したのは私だが（room [41]）、
確かめたのは「ディレクトリ名 == store の project_id」が偶然成立する project だけだった。**
ズレる経路を見ていなかったのが、この欠陥を通した直接の原因。

## 変更

`skill/scripts/external-pane.mjs`:

- project_id の決定順を **既存 identity → store manifest（`.lattice/todo/manifest.json` の `project_id`）→
  ディレクトリ名** にした。store があればそれが正
- manifest は**直接読む**（`lattice` CLI を起動しない）。PATH に CLI が無くても動き、
  常駐 daemon にも触れない
- **既存 identity の `project_id` は書き換えない**（人が書いた値が正・設計メモの指示どおり）。
  ただし store と食い違う場合は**黙って進めず stderr へ警告**を出す——このまま setup を続けると
  `lattice todo status` が落ちるため、画面に出ない失敗を作らない

## 検証

`experiments/external-pane-project-id-repro.mjs`（新規）。temp に **PascalCase ディレクトリ
`RootSitePromotion`** を作り、**kebab-case の project_id** で store を初期化して食い違いを実際に作る。
`lattice` は実物を起動する（`lattice plan create` / `lattice todo status`）。

| 実行 | 結果 |
| --- | --- |
| `--broken`（負のコントロール＝旧挙動でディレクトリ名を書く） | **FAIL** project_id 不一致／**FAIL** `lattice todo status` が `PROJECT_IDENTITY_INVALID` で死ぬ／rc=1 |
| 現行実装 | **PASS** project_id が store と一致／**PASS** external_pane 書込／**PASS** `lattice todo status` が生きて `project_id` を返す／rc=0 |
| `--preexisting` | **PASS** 既存 identity の `project_id` と `display_name` を保ったまま `external_pane` だけ足す |
| 食い違い時の警告 | stderr に「既存 project.json の project_id="wrong-id" が Lattice store の "real-id" と食い違っている…」が出る（実行して確認） |

### ハーネス自身の欠陥を1つ潰した記録

最初、ハーネスから `LATTICE_DASHBOARD_AUTOSTART=0` を渡していた（共有 daemon を起こさないため）。
すると **負のコントロールが PASS してしまった**——identity 解決は dashboard 登録の経路に乗っているので、
autostart を切ると**欠陥そのものが再現しない**。**測定器が対象を検出できることを先に確かめる**
（決定58）をやっていなければ、「現行実装 all pass」だけを見て**何も検出しないハーネス**を置いていた。

正しい隔離は `LATTICE_DASHBOARD_RUNTIME_DIR` を temp へ逃がすこと（登録簿は利用者の
`~/.lattice/dashboard` を触らない・autostart は切らない）。あわせて **project_id を実行ごとに変える**
（登録簿は project_id を鍵に repo root を覚えるので、固定値だと前回の消えた temp dir と衝突して
`PROJECT_ROOT_CONFLICT` になる。これは製品でなくハーネスの問題）。
