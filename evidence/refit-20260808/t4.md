# t4 監査の卓内化の正典改訂 — haruka

## 何を変えたか

### `skill/SKILL.md`（親の operating notes・SKILL.md 直列の先頭）

- **親の権能から「監査」を外し「受理判定」へ**。従来「進行・承認・監査・督促・オーナーとの接点」だったものを
  「進行・受理判定・督促・オーナーとの接点」に改めた
- 追加した項（決定60 の要点）:
  - 完了 task の監査は**実装者以外の席**が実物（diff・検証結果・ハーネスの正負両方）を読んで行い、
    **所見を room へ出す**。親がするのは受理の宣言だけ
  - **受理の根拠は「所見が room に出ていること」**。親自身の読みを根拠にすると親が最終判断者へ戻り、
    決定43 が塞いだ経路（親が言い直すと出典が親へ書き換わる）と同じ形になる
  - **監査者は自分の測定器を先に疑う**（欠陥版で落ちることを確認してから green を読む）
  - 監査の依頼は実装者が出す。依頼が無くても手が空いた席は出た順に読んでよい
  - 指摘は**欠陥の断定と申し送りを分けて書く**（受入条件外なら記録先まで示す）
- 併せて **ichika [215] から渡された1行**（`--phase` で卓の claim 範囲を絞る）を setup 手順3へ入れた。
  ichika は SKILL.md 直列の外なので、直列の先頭を持つ私が代理で入れる約束（room [223]）の履行

### `skill/templates/member.md`（メンバー側の作業ループ）

- 作業ループへ2項: **完了報告に「この点を見てほしい」を添える**／**ready が無い時は他席の done を監査する**
  （実物を自分で走らせる。**報告を読むだけでは監査にならない**）
- 注意へ1項: **監査する時は自分の測定器を先に疑う**——`cmd | tail` の終了コードは tail のもの・
  隔離の仕方で欠陥そのものが消えることがある

### `docs/plan.md`

- **決定59**: 卓の claim 範囲を phase で縛る（ichika の t8）。`setup.sh:6` のコメントが参照している番号に
  実体が無い状態だったので、実体を書いた。内容は ichika の証跡と room 宣言から起こし、**強制が文書止まりで
  `lattice todo start` は phase を見ない**という残課題まで含めた
- **決定60**: 監査の卓内化。**本 campaign の実運用で出た3件を根拠として書いた**
- **§11 課題帳（未着手）**: 共有 branch への push が他人の未監査 commit を巻き込む問題。
  **kotoha [225] の基準**（「他人の commit」ではなく「他人の**未監査** commit」）を採った

## どう確認したか

**この task は「検出器」ではないので、欠陥版で落とす形の負のコントロールは取れない。** 代わりに次を確かめた。

1. **決定59 の記述が ichika の実装と一致するか**を実物で照合した:
   - `skill/scripts/setup.sh` — `--phase` は位置引数の後ろ（`shift 6` の後にループ）、複数可、
     不正な id と未知の引数は rc=1、**scaffold より前に検証**（残骸を残さない）
   - `setup-state.json` へ `phases` が**追加キー**として入る（既存キーは不変）
   - `skill/templates/member.md` の `{{CLAIM_SCOPE}}` に setup が範囲を焼き込む
2. **決定60 の3つの根拠が room の実物に存在するか**を発言番号で照合した（mio [210]／ichika [202]／
   私自身 [226]）。**私が書いた根拠のうち1件は私自身の失敗**である（監査の一手目で `| tail -6` の rc を
   読んだ）——他人の失敗だけを根拠にしていない
3. **SKILL.md 直列の約束を守ったか**: 私が触ったのは「親の operating notes」と「setup 手順3」だけで、
   kotoha が t6 で入れた env 規約の節（`export` 付き）には触っていない（`git diff` で確認）

## 監査してほしい観点（決定60 を自分に適用する）

- **決定59 を私が書いたことの是非**。room [232] で「59 は空けておく」と言った後、[241] で前言を変えて
  自分で書いた。理由は出したが、**ichika の task の記述を実装者以外が書いている**——事実の誤りが無いかを
  **ichika 本人**に見てほしい
- **決定60 が「監査を増やす」方向へ倒れていないか**。決定48 の最小主義に反していないか。私は
  「親が読まない代わりに卓が読む」で総量は変わらないつもりだが、条文としては増えている

  **手が空いた席が監査へ流れる**——これが「遊休席を作らない」として働くか、「監査の水増し」になるかは
  次の campaign の観測待ち
