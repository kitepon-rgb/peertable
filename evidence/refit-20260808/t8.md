# t8 member claim範囲のphase束縛

担当 ichika。触ったのは `skill/scripts/setup.sh` と `skill/templates/member.md` の2本だけ。
**`skill/SKILL.md` には触っていない**（bell [182] の直列化で SKILL.md は t6→t4→t9→t3 の列にあり、私はその列に居ない。
手順書側へ書く必要が出たら room へ出して順番に入れてもらう）。

## 作ったもの

複数 phase の plan へ別 campaign が相乗りする時、**範囲外 phase の task を claim する越境**が2回実測された。
その恒久対処として、**卓の claim 範囲を setup 時に決めて、席へ渡す文書へ焼き込む**。

- `setup.sh` へ **`--phase <id>`（複数可）** を追加。位置引数の後ろに置く形で、既存の呼び出しは1文字も変えずに通る
- `setup-state.json` へ **`"phases": [...]`** を追加（空配列＝plan 全体）。**追加キーなので既存の読み手を壊さない**
  （`teardown.sh` は必要キーを名指しで読み、新しめのキーは `.get(...)` で読んでいる）
- `member.md` テンプレートの作業ループ手順1へ `{{CLAIM_SCOPE}}` を置き、setup が実際の範囲を差し込む:
  - phase 指定あり → 「**この卓の claim 範囲は phase p2 p3 の task だけ**。範囲外の phase の task は、ready に
    見えていても取らない——同じ plan へ別 campaign が相乗りしている時、範囲外を取ると他卓の工程を横取りする
    （越境が2回実測されたことへの対処）。範囲外に手を入れる必要が出たら room へ出して裁定を仰ぐ」
  - 指定なし → 「この卓の claim 範囲は plan 全体（phase 指定なしで立っている）」

**理由まで文書へ書いた**のは意図的。理由の無い規則は、次に読む人が「なぜ縛られているか分からない」まま外すため。

## 検証

`bash -n` 構文チェックのほか、**実際に setup を走らせて生成物を読む**形で6経路。

| 経路 | 結果 |
| --- | --- |
| ① `--phase p2 --phase p3` | `setup-state.json` = `phases: ['p2','p3']`／member.md に「claim 範囲は phase p2 p3 の task だけ」 |
| ② phase 指定なし | `phases: []`／member.md に「claim 範囲は plan 全体（phase 指定なしで立っている）」 |
| ③ 単独円卓モード + `--phase` | **rc=1**「単独円卓モードに --phase は使えない（工程正本を持たないため）」・**`.team/` の残骸ゼロ** |
| ④ 不正な phase id（`bad;id`） | **rc=1**「phase id に使えない文字がある」・**残骸ゼロ** |
| ⑤ 未知の引数（`--phases`） | **rc=1**「未知の引数: --phases（--phase <id> だけを受ける）」・**残骸ゼロ** |
| ⑥ 既存呼び出し（引数を足さない） | ①②のとおり従来どおり通る＝**後方互換** |

③〜⑤で**残骸ゼロ**なのが要点。引数の検証は project へ何か置く前に済ませる（不可侵原則＝半端な `.team/` を残さない）
という既存の設計に合わせて、検証を scaffold より前に置いた。

**負のコントロールの考え方**: この task は「検出器」ではなく「文書と状態への焼き込み」なので、
欠陥版を落とす形の負のコントロールは取れない。代わりに **失敗経路が本当に止まること（rc=1）と、
止まった時に何も書かれていないこと**を確認した——「通ることだけ見ない」の、この task における形。

## 残すもの

- **範囲の強制は文書止まり**。`lattice todo start` は phase を見ないので、**機械的には範囲外の claim を止められない**。
  止めるなら Lattice 側に phase 束縛の口が要る（本 campaign の受入条件外）。いまは「席が読む文書に範囲が書いてある」
  ところまでで、破ったら room の宣言と工程正本の突き合わせで見つかる形
- `skill/SKILL.md` の setup 手順に `--phase` の説明は入れていない（直列化の列の外なので）。**SKILL.md を持つ席が
  入れるべき1行**: 「複数 phase の plan へ相乗りする時は `--phase <id>` で卓の範囲を絞る」
