# t6 teardown.sh の沈黙中断修正

担当: kotoha / 2026-08-08 / plan `refit-20260808`
対象: `skill/scripts/teardown.sh`・`skill/SKILL.md`（env 規約と teardown の節）・`experiments/teardown-silence-repro.sh`（新規）

## 直す前に、壊れ方を再現した

「直ったか」を判定できるようにするため、**先に測定器（再現ハーネス）を作り、旧版で落ちることを確認**してから実装した。
使ったのは使い捨ての project と使い捨ての room server（別ポート）だけで、**本番にも他の席にも触っていない**。

旧版（`HEAD:skill/scripts/teardown.sh`）の実測:

| 条件 | exit | 出力 | 撤去 |
| --- | --- | --- | --- |
| `PEERTABLE_POST_TOKEN` が空 | 22 | **1文字も出ない** | `.team`・`.mcp.json`・`.lattice`・exclude 追記行がすべて残る／room も生きたまま |
| token が誤り（403） | 22 | **1文字も出ない** | 同上 |
| server 不達 | 7 | **1文字も出ない** | 同上 |
| 正常 | 0 | `teardown done` | 完了 |

真因は 25 行目の `curl -sf … > /dev/null` と `set -e` の組み合わせ。`-f` が非2xx を非ゼロ終了に変え、`set -e` が
**何も言わずに** script を止めるので、room 削除より後の撤去段が全部未実行のまま残る。

### 設計メモの真因記述との差分（実測で否定した1点）

設計メモは「**room 既削除後の再実行も404で同型**」と書いているが、**現行 server では再現しない**。
`room/server.mjs` の `DELETE /api/<room>` は `loadRoom(name, create=true)` で room を作ってから消すため、
存在しない room への DELETE も **200** を返す（実測: `DELETE /api/nosuchroom2 -> 200`／その条件で旧 teardown は exit 0 で完走）。
同型の無言中断を起こすのは **「server 不達」と「token 誤り」** の2つ。対処の必要性は変わらないので裁定は仰がず、
事実だけ room [193] へ出した。

## 直した形

**方針**: 沈黙を消すのが目的で、止めるのが目的ではない。**トークンを要するのは room 削除だけ**なので、
そこが失敗しても**トークンを要さない撤去段は続行**し、未実施を明示して非ゼロで終わる（room [190] で宣言・異論なし）。

- **(a) token 空を typed error として即時報告**: `TOKEN_MISSING` と、`~/.config/peertable.env` の定義が `export` 付きでないと
  子 process へ渡らないことまで書く。**報告して終わりにはせず、残りの撤去は続ける**
- **(b) room DELETE を冪等化**: `-sf` をやめて `-w '%{http_code}'` で**コードを表示**。200 なら `[実施]`、それ以外は `[未実施]`＋
  「403/401 はトークン不一致、000 は server 不達」の読み方を添える
- **(c) 各段が `[実施] / [スキップ] / [未実施]` を1行ずつ出す**（wakeup-bridge / room / 外部ペイン / `.team` / `.mcp.json` /
  exclude ×2 / `.lattice`）
- **(d) 未実施があれば「手当」の1行を出す**: `.team/` を消すと room 名と URL も消えるので、**後から手で消せる curl を先に出す**。
  最後に「未完了。撤去済みの段は冪等なので原因を直せば再実行して安全」と述べて **exit 1**

`SKILL.md` は2箇所: 前提の env 記述を **`export PEERTABLE_POST_TOKEN=…`** へ改訂（`export` 落ちが今回の起点だったことを併記）、
teardown の節へ「各段が1行ずつ出る／room 削除だけがトークン依存／未実施が出たら手当してから再実行」を追記。

## 検証

再現ハーネス `experiments/teardown-silence-repro.sh`（第1引数で対象 teardown を差し替えられる）で4ケース。
判定は **exit code・出力があること・撤去し残しゼロ** の3点をすべて満たすこと。

| 対象 | 結果 |
| --- | --- |
| **修正版** | **pass 4 / fail 0**（token 空・token 誤り・server 不達 は exit 1 で報告つき完走、正常は exit 0） |
| **旧版（負のコントロール）** | **pass 1 / fail 3** — 3ケースとも「出力なし・残存あり」で落ちる |

**負のコントロールが本体**: 修正版が通ることだけを見ていたら、何も検出しないハーネスを置いた可能性がある。
**旧版で落ちること**を確かめて初めて、4/4 に意味が出る（前 campaign 決定58 の「測定器が対象を検出できることを先に確かめる」）。
