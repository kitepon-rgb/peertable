## 何を書いたか

決定51（メンバーの再着任）の**親版**。**卓は生きたまま親だけが記憶を失う**局面なので、
「復帰は記憶ではなく正本から取り直す」を4段の順序として書いた。

1. **room ログを読む** — `messages?since=<最後に読んだ seq>`（無ければ 0 から）。会話が卓の正本なので、まず現在地を作る
2. **工程正本で照合** — `lattice todo status --json`。room の宣言と食い違ったら**工程正本が正**で、食い違い自体を room へ出す
3. **`parent-join.sh` を再実行しない** — 親の member 登録はセッションを跨いで残る。`members` で自分の名前を確認するだけ
4. **SSE を張り直す** — 前の Monitor は死んでいるので、張り直さないと以後の新着に気づかない

**やらないこと**も書いた: 復帰の挨拶を全員宛で流さない（1発言=全席1ターン）／作業の再確認を席へ聞いて回らない
（現在地は1〜2で取れるので、聞くのは席の時間を奪うだけ）。

## 検証（書いた内容が実物と一致するか）

文書 task なので欠陥版を落とす負のコントロールは取れない。代わりに**4段すべてを実物で確かめた**。

| 書いたこと | 確かめ方 | 結果 |
| --- | --- | --- |
| `messages?since=` で続きが読める | 本番 room へ read-only で `since=250` | **7件・先頭 seq=251**＝`since` より後だけが返る |
| 親の member 登録がセッションを跨いで残る | 本番 room の `members` | **`bell` が 12:04:06 の登録のまま在籍**（親のセッションは以後入れ替わっている） |
| `parent-join.sh` の再実行が「参加した」を二重に流す | `room/server.mjs` の `POST /members` を直読み | **`post(room,'system','all', '<名前> が参加した')` が `if (!room.members.has(name))` の外**にある＝**既存メンバーでも system 発言が必ず出る**。設計メモは「再実行は不要」までだったが、**再実行すると実害（席が「新しい親が来た」と誤読する）が出る**ことまで確認できたので、そこまで書いた |
| 前の Monitor は死んでいる | 本 campaign の実例（room 停止40分の間に SSE が切れ、bell が張り直している） | room [248] の記録と整合 |

**設計メモより1歩踏み込んだ点（申告）**: メモは (3) を「member 登録が残っていれば再実行は不要」と書いていたが、
**再実行すると何が起きるか**まではコードで確かめられたので、**理由込み**で書いた。理由の無い禁止は次の人が外すため。
