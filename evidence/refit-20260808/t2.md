# t2 証跡 — done.sh へ未push本数の表示1行

担当: mio / plan: refit-20260808 / 2026-08-08

前 campaign で**私自身が踏んだ穴**を塞いだ。t7 の成果物3本（publish の機械 gate 自体・証跡・正典追記）を **done 宣言の後も未 push のまま取り残し**、親の監査に拾われた。塞ぎ方を提案したのは kotoha（前 campaign room [169]）、§11 へ課題として置いたのは私。

## 何を入れたか

`skill/templates/done.sh`（正本）と `.team/scripts/done.sh`（卓のローカル・git 管理外）の両方へ、`lattice todo done` の直後に7行:

```sh
unpushed=$(git rev-list --count '@{u}..HEAD' 2>/dev/null || true)
if [ -n "$unpushed" ] && [ "$unpushed" != 0 ]; then
  echo "未push ${unpushed}本: この done の成果物はまだ upstream へ着地していない" >&2
fi
```

**設計の要点3つ**（いずれも本文にコメントとして残した）:

1. **出すだけで止めない。** push 既定でない repo も、まとめて push する運用も壊さない。止める gate にすると、push 権限を持たない席が done を打てなくなる
2. **`done` の後に置く。** 完了の定義が成り立たなければならない唯一の時点で、かつ**全員が必ず通る場所**。publish 経路の機械 gate（決定58 の `prepublishOnly`）は tarball しか見ないので、docs・証跡・`experiments/` はその外側にある
3. **upstream 未設定・git 管理外でも `done.sh` 自体を死なせない。** `@{u}` は upstream が無いと `fatal` を返す。`set -e` の下で素通しにすると **done.sh が止まる**——**沈黙する失敗を塞ぐ部品が、同じ形で止まっては本末転倒**。`2>/dev/null || true` と空文字チェックでガードした

## どう確認したか

設計メモの3ケースに **「git 管理外」を4つ目として足して**実測した（`set -e` の下で当該ロジックだけを同条件で走らせ、検査の後も実行が継続することを毎回確認）。

| 条件 | 出力 | 実行継続 |
| --- | --- | --- |
| git 管理外のディレクトリ | なし | **継続** |
| upstream 未設定（`git init` 直後・commit 1本） | なし | **継続** |
| upstream 有り・未push 0（本 repo） | なし | **継続** |
| **未push 2本**（bare repo を upstream にして2本先行） | **`未push 2本: この done の成果物はまだ upstream へ着地していない`** | **継続** |

**負のコントロールを先に取った。** 「未push がある時に実際に検出できる」ことを確かめてから、他3ケースの「何も出ない」を読んでいる。順序が逆だと、**何も検出しない検査を置いたことに気づけない**（前 campaign で、旧 UI を新 UI のセレクタで数えて300秒すべて0という空振りが実際に起きている）。

`bash -n` で両ファイルの構文も確認。

**この証跡を閉じる `done.sh` の実行そのものが、5ケース目の実地確認**になる——本 repo は upstream 有りなので、証跡を commit した直後に叩けば「未push 1本」が出るはず（commit したが push していない状態）。出れば実運用の経路で動いたことになる。
