# h4 — setupがgit追跡済みteam資産を上書きしない

## 実装

`skill/scripts/setup.sh` の全生成処理より前に `.team/` の既存パスを調べ、git追跡済み資産と未追跡の既存資産を `PEERTABLE_SETUP_TEAM_CONFLICT` として分類して停止するようにした。前卓の残骸か利用者資産かを setup が推測して退避・削除・上書きする経路は追加していない。空の `.team/` だけは従来どおり生成できる。

`experiments/setup-team-ownership-repro.mjs` は、追跡済み `.team/scripts/done.sh`、未追跡の既存 `.team` 資産、clean project の3 fixtureを作る。負の2ケースは既存資産、git status、`.git/info/exclude`、`.mcp.json`、生成前の `.team` を保全し、cleanケースは setup → `teardown.sh --purge` 後の差分ゼロを確認する。

## 文脈近接監査

h6audit の [498] が凍結2パスを実物監査した。指定fixture、追跡済み／未追跡の両負制御、clean setup→purge teardown、全writeより前の競合検査、退避・削除・上書き・path traversalの追加経路を確認し、欠陥なしと判定した。監査席による変更・commit・Lattice書込はない。
