## 負例

t4 の使い捨て room / project / 実 Codex 席で、DM 読み取りと active 席の自律 progress / claim を
通過した後、修理前の `change-seat.sh --effort max` を実行した。旧 member が残ったまま
`launch-seat.sh` へ進み、`SEAT_ROOM_MEMBER_CONFLICT` で停止した。既存の rollback も同じ衝突で
停止したため、外部から手動 `leave-seat.sh` を足して成功扱いにはしなかった。

独立した負例として、修理後の t4 実測でも同名 member を残したまま `launch-seat.sh` を直接呼び、
`SEAT_ROOM_MEMBER_CONFLICT` で拒否されることを確認した。これは `launch-seat.sh` の安全境界を
維持したまま、呼び出し側が正規退席を先に行うことを検証する負例である。

## 修理

`change-seat.sh` は target の引数・busy・live catalog 検証を終えた後、同じ script tree の
`leave-seat.sh` を呼ぶ。旧席の session、room member、seat identity、credential の撤去が成功した
時だけ `launch-seat.sh` を実行する。撤去に失敗した場合は新席を起動しない。新設定の起動失敗時は
既存の旧設定 rollback を一回だけ試みる。

Reiのread-only peer audit（#1121/#1122）は、`58d648c` がこの置換境界を満たす一方、履歴POST後の
room履歴GET読返しと `from/to/body` 照合を欠く具体的DEFECTを確定した。`526ccc3` ではPOST応答の
`seq` を束縛し、同じ `seq` をGETで読み返して `from/to/body` がtargetと一致しない場合は
`SEAT_CHANGE_CHANGED_BUT_HISTORY_FAILED` で非0終了する。不在・不正なPOST応答・GET失敗も成功扱いにしない。
