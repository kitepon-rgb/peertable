## 2. 作ったもの

- **`skill/scripts/change-seat.sh`（新規）** — 親が確定した target だけを明示引数で受ける共通操作。
  `change-seat.sh <project_dir> <member> [--model <model>] [--effort <effort>] [--parent <name>] [--reason <text>]`
  - room の発言を**読まない**（GET /messages は消えた。POST は履歴の記録だけ）
  - 現在の vendor / model / effort は room の member metadata から取る
  - target の検証は live 面だけ:
    - claude → `claude --help` の `--effort <level>` 行が列挙する水準（hardcode 表を持たない）
    - codex → `codex debug models` の slug と `supported_reasoning_levels`
    - **claude の model 名は事前検証しない**。非破壊 catalog が無く、`--help` の alias 例は catalog では
      ないため（実際 2026-08-11 に `fable` は例に載ったまま live では unavailable だった）。
      実 CLI の起動失敗と rollback が正式な検証境界である（計画 §2.1）
  - 同値なら再起動しない（`SEAT_CHANGE_NOOP`）／busy 席は停止しない（判定文字列は seat-status-bridge と同じ
    `esc to interrupt`）／vendor 変更は引数の時点で拒否
  - 再起動後に member metadata を読み返して model と effort の両方を照合する
  - 起動失敗時は旧 model / 旧 effort へ**1回だけ**明示 rollback し、別設定へ黙って落ちない
  - 成功・部分失敗を room 履歴（`[席設定変更] …`）へ残す
- **`skill/scripts/change-effort.sh`** — 配布済みの effort 専用入口を互換 wrapper へ。引数の形
  `<project_dir> <member> <effort> [parent_name]` は保ち、完全一致DM検査は持たない。
- **`room/client.mjs`（配布診断）** — `skill_bundle` の必須一覧へ `scripts/change-seat.sh` を追加。
  梱包漏れを diagnostics が検出する（必須 19 ファイル）。
- **`experiments/seat-change-repro.mjs`（新規）** — 新契約の再現ハーネス（22 check）。
- **`experiments/effort-change-repro.mjs`（改修）** — 「完全一致DM検査が戻ってくる」退行だけを止める
  ハーネスへ縮小（5 check）。role 文書への assert は落とした（role 文書は t2 の所有で、当の protocol を
  取り除く工程が動いているため、t1 の harness が旧文面を要求し続けると t2 を機械的に妨害する）。
