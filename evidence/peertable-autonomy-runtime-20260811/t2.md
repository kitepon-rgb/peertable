# t2 メンバーの自律ループと相互監査を role へ戻す

## 何を作ったか

`skill/templates/member.md`・`skill/templates/member-standalone.md`・`skill/templates/charter.md`
を campaign §2.2/§2.3 の順序へ合わせて書き換えた。

1. **監査が Lattice 完了より前に来る順序へ変更**（§2.2）。
   - 旧: 証跡→commit→`done.sh`実行（Lattice `todo done`）→room完了報告（この時に監査を依頼）
     →手が空いたら「他の席の done を監査する」。
   - 新: 証跡→commit→**room へ監査依頼**→監査席が diff・実測を確認→defect-free なら
     `done.sh` 実行（監査所見が付く前に実行しない）→room 完了報告→手が空いたら
     「他の席の**監査依頼**（done 前・未監査）」を探す。
   - `member-standalone.md`（単独円卓モード）も同じ順序（`[監査依頼]` → 監査 → `[done]`）へ揃えた。
2. **探索順 active → ready → 文脈近接 peer audit → 待機 を明記**（§2.3）。作業ループ冒頭に
   1文で追加し、member.md / member-standalone.md 両方に反映した。
3. **active な工程を持つターンは進捗・完了・blocker・明示的待機のいずれかを記録せずに終えない**
   という規律を明記した（目的4）。親の局所的な簡潔化要求はこの記録義務を止めないこと、止めてよいのは
   オーナーの明示 pause・承認待ち・外部依存待ち・実在 blocker だけであることも明記。
4. `charter.md`（憲章）に、①進捗記録義務を止めない条件（2項へ追記）、②各工程の完了は文脈近接一席の
   監査を経てから成立する原則（新設11項）を追加し、role文書3つで一貫させた。
5. リスト番号のずれ（`member.md` の手順 8 の後で 9/10 が二重に使われていた編集ミス）を振り直した。

Lattice の実行層節（pull型）のステップ「終わったら `todo done` を打ってから accept する」も、
「監査で defect-free の所見が付いたら」と明確化した。

## どう確認したか

新規ハーネス `experiments/member-audit-before-done-repro.mjs` で、書き換えた3ファイルの本文を
文字列アサーションで検証した。

```
$ node experiments/member-audit-before-done-repro.mjs .
  pass  member.md: 監査依頼が done.sh 実行より前に書かれている — auditIdx=1866 doneShIdx=2165
  pass  member.md: 監査所見が付く前に done.sh を実行しないと明記
  pass  member.md: active→ready→文脈近接peer audit→待機の探索順を明記
  pass  member.md: active turnを記録せず閉じない規律を明記
  pass  member.md: 旧「他の席の done を監査する」文言が除去されている
  pass  member-standalone.md: 監査依頼が [done] 宣言より前に書かれている — auditIdx=1325 doneIdx=1571
  pass  member-standalone.md: 監査所見が付く前に[done]を出さないと明記
  pass  member-standalone.md: active→ready→文脈近接peer audit→待機の探索順を明記
  pass  charter.md: 監査前に完了状態にしない原則を明記
  pass  charter.md: turnを記録せず終えない規律を明記
member audit-before-done repro: green
```

修正前（このハーネスを旧版に対して実行した場合）は「監査依頼が done.sh 実行より前に書かれている」
「旧『他の席の done を監査する』文言が除去されている」等が FAIL することを、編集前の内容から確認済み
（旧文言「7. room に完了を一行報告する...決定60」「8. 手が空いていて ready が無いなら、他の席の
done を監査する」が実際に存在していた）。
