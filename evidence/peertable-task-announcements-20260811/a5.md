## 3. transport実動結果

### 3.1 クリーンな通常API実測

使い捨てroom `a5-wave1-20260811-remedial-tsubaki` に送信席と観測席を置き、正しいMS-A2 endpointへ接続した。
`GET /api/rooms/<room>/messages?since=2` の結果は、受理されたtask eventのseq3/seq4だけだった。

- `started` transition: HTTP 200、seq3、`idempotent=false`、生成body、宛先は観測席とbell、送信者自身は除外
- 同じ `started` transitionの再送: HTTP 200、seq3、`idempotent=true`
- `completed` transition: HTTP 200、seq4、`idempotent=false`
- 通常broadcast (`to: "all"`): HTTP 400、`EXPLICIT_RECIPIENT_REQUIRED`
- 未知kind: HTTP 400、`TASK_EVENT_KIND_INVALID`
- 自由body: HTTP 400、`TASK_EVENT_BODY_FORBIDDEN`
- 同じtransition keyで内容を改変: HTTP 409、`TASK_EVENT_TRANSITION_CONFLICT`
- 拒否された入力はmessagesへ永続化されなかった

### 3.2 SSE同一接続実測

別使い捨てroom `a5-wave1-20260811-remedial-sse-tsubaki` で、独立席AmpereがSSEを接続したまま、
同じ接続へ次の2イベントを流した。Ampereの接続開始表示は `: connected seq=2` であり、接続を張り直さずに
seq3 `started` とseq4 `completed` を受信した。観測は120秒の同一streamで完了し、SSEで両transitionを
受信したことをAmpereがroomへ報告した。
