## 受入の過程で親が見つけて直した欠陥（席の完了報告後）

1. **`ensure-bridge.sh` が record を JSON として壊していた**——`"\\n"` が JS でリテラルの `\`+`n` になり、
   `require` も `JSON.parse` も落ちる。teardown の `--stop` も bridge の再起動も不能になる
2. **死んだ常駐の stale `ready_at` で success を返していた**——「起動していないのに起動したと言う」＝
   この supervisor が塞ぐはずの穴そのもの
3. **tmux セッションへ env を渡していなかった**——新 session が継ぐのは tmux *server* の環境で、
   呼び出し元 client の環境ではない。`PEERTABLE_TMUX_SOCKET` の手渡しが消え、常駐が本番の既定 socket を
   観測しにいっていた（受入で legacy 席の status が入らず発覚）

また、席が提出した `experiments/bridge-supervisor-repro.sh` は **`ensure-bridge.sh` を一度も呼んでいなかった**
（使い捨て socket に `sleep` を1つ立てて `has-session` するだけ）。実物を呼ぶ5件（ready_at 待ち・冪等・
親シェル消滅後の生存・stale ready_at・失敗時の非ゼロ）へ書き直し、**1 と 2 はこの書き直しで発見した**。
