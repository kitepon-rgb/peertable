# f2 `ensure-bridge.sh` 再 arm 時の空配列展開

担当: tsubaki。実装 commit: `478de1b`（監査前の WIP）。

## 負例

macOS 標準 bash 3.2 の `set -euo pipefail` 下で、死んだ stale record の `args: []` を
持つ一時 project に次を実行すると、修正前は次で停止した。

```text
rc=1
skill/scripts/ensure-bridge.sh: line 13: saved[@]: unbound variable
```

再 arm 前の record 復元で空配列を無条件に `set -- "${saved[@]}"` へ展開していたため、
bridge 消失後の復帰契約が成立しなかった。

## 実装

- `skill/scripts/ensure-bridge.sh`: `saved` が空なら現在の引数なしを保ち、要素がある時だけ
  positional arguments を復元する guard を追加した。
- `experiments/bridge-supervisor-repro.sh`: 測定器自身の `$p1）`／`$p2）` の `set -u` 誤爆を
  `${p1}`／`${p2}` へ修正し、stale record の d ケースを引数なしで実行して空 `args` 経路を
  実際に通すようにした。

## 実測

```text
$ bash -n skill/scripts/ensure-bridge.sh experiments/bridge-supervisor-repro.sh
$ bash experiments/bridge-supervisor-repro.sh
(a) ...

  ok: 2回目は同じ pid のまま
  ok: 親シェル消滅後も常駐が生存
  ok: stale ready_at を無視して建て直した（pid 57264 → 57554）
  ok: 非ゼロで落ち、ログ末尾を出した
bridge supervisor repro: 5/5 green
MEASURED_RC=0
```

修正 guard を一時的に除いた mutation では d ケースで次を再現し、ハーネスが本体欠陥を
見逃さないことを確認した。

```text
mutant_empty_array_rc=1
ensure-bridge.sh: line 15: saved[@]: unbound variable
FAIL: (d) ensure が非ゼロ
```

測定器の変異も、最初の実行で `$p1）`、次の実行で `$p2）` が本体測定を遮った。両方を
修正してから上記 5/5 を取得した。PT​​Y の sentinel 終了値ではなく、`MEASURED_RC` と
スクリプト本文の失敗行を正として判定した。
